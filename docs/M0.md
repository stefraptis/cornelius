## What was built

**Database** (`supabase/`). Three migrations: accounts and hierarchy
(profiles, organizations, org_memberships, teams, team_memberships,
workspaces, invitations); procedures, model_versions, videos, video_shares,
jobs, analyses, phase_segments, tool_segments, scene_events,
frame_predictions, highlights, audit_log, streaming_usage; and row-level
security. A new auth user automatically gets a profile and a personal
workspace. A new team gets a team workspace and its creator as `team_owner`.
Logins are audited by a trigger on `auth.users.last_sign_in_at`.

The seed registers five procedures. Only `lc` has `analysis_enabled = true`
and a model version (`lc-effnetv2s-bilstm-v1`) carrying the seven phase
labels, seven instrument labels with display names and fixed colors, and the
published Cholec80 metrics (phase balanced accuracy 95.73 ± 0.59 %, tool mAP
95.47 ± 0.82 %). Nothing in the app hardcodes cholecystectomy.

Phase corrections are a versioning scheme: `phase_segments.version = 0` is
the raw model output and cannot be changed by any user; a correction is a new
version with `verified_by` set, insertable only by the owner or a team mentor.

**API** (`api/`). FastAPI with Supabase JWT verification (legacy HS256 secret
or JWKS), a connection pool that can run queries as the signed-in user so RLS
applies inside the API too, the storage module (S3 API only: presigned reads,
multipart uploads with resume, prefix deletion that refuses root prefixes,
HLS playlist rewriting), an audit writer, and three routers: `/health`,
`/me`, `/procedures`.

**Web** (`web/`). Next.js 16 App Router with Tailwind v4 and the Section 14
tokens as CSS variables, IBM Plex self-hosted, light and dark themes, a
collapsible sidebar with workspace switcher, sign in with password or email
link, sign up, password reset, TOTP enrollment and challenge, a profile page,
an "About the model" page fed by `/procedures`, and placeholder pages for
later milestones. All strings are in `src/messages/en.json`.

**Workers** (`workers/`). The shared job loop (claim, succeed, retry with
exponential backoff, final failure) with tests. Transcode and analysis
handlers are stubs until M1 and M2.

## How to run the demo

```bash
# 1. Local database with migrations and RLS tests
make db-local
cd api && python -m venv .venv && . .venv/bin/activate && pip install -e ".[dev]" requests
pytest -q            # 55 tests

# 2. Frontend without Supabase: design review page
cd web && pnpm install && pnpm dev
# open http://localhost:3000/dev/shell (sample data; light/dark toggle top right)

# 3. Full sign-in flow needs the Supabase project (below), then:
cp .env.example .env   # fill SUPABASE_* and NEXT_PUBLIC_*; copy NEXT_PUBLIC_* into web/.env.local
make api-dev && make web-dev
```

## Decisions made while building (within the guideline)

- Local development uses a plain PostgreSQL 16 cluster with a small shim (`auth` schema, `auth.uid()`, roles) instead of the Supabase Docker stack, so RLS tests run anywhere in a few seconds, including CI.
- Supabase grants all table privileges by default; the RLS migration revokes them and grants exactly the matrix, so a forbidden write fails with "permission denied" rather than silently affecting zero rows.
- Select policies on `videos`, `teams` and `organizations` include the owner or creator inline so `insert ... returning` works in one statement.
- Workspace selection is stored per browser for now; it becomes server state when teams arrive (M4).
- Next.js 16 uses `proxy.ts` (the renamed middleware) for session refresh and second-factor enforcement.
